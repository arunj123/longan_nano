  8. INDEPENDENT ROOT CAUSE ANALYSIS & DIAGNOSTIC FINDINGS
================================================================================

1. Multi-Packet Streaming Behavior on GD32VF103 / Synopsys DWC2:
   - DWC2 handles native multi-packet transfers (64-byte chunks) seamlessly.
   - For an 8-sector (4096-byte) read, all 8 sectors (512 bytes each) were sequentially
     loaded into TX FIFO 1 without FIFO underrun (DIEPINTF_TXFUD never asserted).
   - Packet count (PCNT) in DIEPLEN correctly decremented from 64 to 0.

2. The Race Condition: CSW Handover Timing vs Linux xHCI URB Retirement:
   - When the 64th data packet was transmitted and ACKed, DWC2 asserted DIEPINTF_TF.
   - The MCU USB ISR immediately transitioned state to STATUS_PENDING.
   - Within 18 microseconds (433 ticks), msc_core::poll() verified that all hardware
     completion flags were set (hw_done, fifo_empty, ep_disabled, sw_done, no_pending)
     and immediately called csw_send().
   - csw_send() loaded the 13-byte CSW into TX FIFO 1 and re-armed Endpoint 1.
   - However, the Linux xHCI root hub takes 50 to 500 microseconds to handle the completion
     interrupt of the 4096-byte Data URB and retire it in the host kernel.
   - Because Endpoint 1 presented data before the host kernel retired the Data URB, the active
     Data URB pulled the 13-byte CSW packet directly from Endpoint 1!
   - Receiving a short packet (13 bytes < 64 bytes) caused xHCI to complete the Data URB
     prematurely with length 4045 bytes (63 * 64 + 13) and status -121 (-EREMOTEIO).
   - When the host SCSI stack subsequently submitted the CSW URB, the device was already idle,
     resulting in a 30-second DID_TIME_OUT hang.

3. Verified Solution:
   - Enforce a 2,500 us CSW framing guard in STATUS_PENDING:
     Firmware must wait >= 2,500 us after data completion before arming the CSW transfer.
     This gives the host xHCI controller and kernel driver sufficient time (2.5 frames) to cleanly
     retire the Data URB before the CSW packet appears on Endpoint 1.
   - Assert DEPCTL_SNAK prior to SD SPI reads:
     EP1 IN must explicitly assert DEPCTL_SNAK during the ~1.5 ms SPI read duration to guarantee
     clean hardware NAK handshakes on the wire while the SD sector is being read.
