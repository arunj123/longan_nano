  9. ROOT CAUSE ANALYSIS & BUILD 0058 SPECIFICATION
================================================================================

A. ROOT CAUSE OF THE LOCKUP ON HOST ERROR RECOVERY:
-------------------------------------------------
1. Bulk-OUT CLEAR_FEATURE NAK Trap:
   In msc_core.cpp::req_handler, when the host issues CLEAR_FEATURE(ENDPOINT_HALT)
   on endpoint 0x01 (Bulk-OUT):
       pcore->regs.er_out[EP_ID(ep)]->DOEPCTL |= DEPCTL_SD0PID | DEPCTL_SNAK;
   Setting DEPCTL_SNAK on the OUT endpoint halts packet reception. The endpoint
   was never re-armed with usbd_ep_recev(pcore, MSC_OUT_EP, ctx.cbw_buf, 31).
   Consequently, the device rejected subsequent CBWs with perpetual NAK handshakes,
   leading to host timeout (-104 ECONNRESET) after 10 seconds.

2. Clobbered Endpoint 1 Configuration in ep1_in_hard_reset():
   In msc_core.cpp::ep1_in_hard_reset, when EPEN == 0:
       er_in1->DIEPCTL = 0U;
   Writing 0 to DIEPCTL strips the endpoint of its core architecture:
     - Bit 31: EPEN (0)
     - Bit 22..25: TXFNUM (becomes FIFO 0 instead of FIFO 1!)
     - Bit 18..19: EPTYPE (becomes Control instead of Bulk!)
     - Bit 15: EPACT (active bit cleared!)
     - Bit 0..10: MPL (maximum packet length reset to 0!)
   Any subsequent usbd_ep_send or usbd_ep_stall was operating on a de-configured
   endpoint, permanently bricking communications until a hardware reset.

B. BUILD 0058 REMEDIATION PLAN:
-------------------------------
1. In msc_core.cpp::req_handler:
   When CLEAR_FEATURE is processed for MSC_OUT_EP:
     - Clear stall and reset toggle to DATA0.
     - Immediately prime the OUT endpoint to accept the next CBW:
       usbd_ep_recev(pcore, MSC_OUT_EP, ctx.cbw_buf, BBB_CBW_LENGTH);
2. In msc_core.cpp::ep1_in_hard_reset:
   Preserve endpoint architectural configuration bits:
     - Retain EPACT, EPTYPE (Bulk), TXFNUM (1), and MPL (64).
     - Never write 0U to DIEPCTL.
3. In poll():
   Ensure watchdog evaluation does not abort transfers during normal, healthy
   SD read operations.
